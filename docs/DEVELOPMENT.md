## How the workflow runs

The "Build and release" workflow (`.github/workflows/release.yml`) only runs when you start it manually from the Actions tab. It has four jobs:

1. Prepare pins `optimistic` and each selected variant branch to a specific commit. It stops right away if a variant is not based on that `optimistic` commit, or if a tag with the same name already exists and `replace_release` is not checked. It also fixes the build user, host and time shared by every build.
2. Optimistic builds the vanilla kernel on `ubuntu-26.04` and saves its ccache to the Actions cache.
3. Variant restores that cache and builds the root variants in parallel. A variant differs from vanilla in only a few files, so almost every object file comes straight from ccache.
4. Release packs each `Image.gz` into an AnyKernel3 flashable zip and publishes a release with English and Chinese notes.

The release tag is the kernel release without its suffix, for example `6.1.177-android14-11-g8ee32a09623b`, where the hash is the `optimistic` commit. Each build also uploads an artifact containing `Image.gz`, `system_dlkm-modules.tar.gz`, `build-info.txt` and `Module.symvers`. The `system_dlkm` modules are not attached to the release.

| Input | Default | Description |
| --- | --- | --- |
| `variants` | `all` | `all`, `none`, or a comma-separated list of ids from `config/variants.json`, such as `ksun,fnsu` |
| `neutron_version` | `06092026` | Neutron Clang build tag, or `latest` |
| `build_user` | `evans` | `KBUILD_BUILD_USER` |
| `build_host` | empty (`github-actions`) | `KBUILD_BUILD_HOST` |
| `build_timestamp` | empty (the build start time) | `KBUILD_BUILD_TIMESTAMP`; any format `date -d` understands |
| `replace_release` | off | Delete and recreate the release with the same tag |

## Using it for your own kernel

1. Fork this repository, then add a repository variable named `KERNEL_REPO` under Settings → Secrets and variables → Actions → Variables, set to your kernel repository, for example `you/android_kernel_common`. The workflow reads it through the GitHub API with the default token, so the kernel repository must be public.
2. Edit `config/variants.json`. Under `base`, set the base branch and its version suffix. Each entry under `variants` needs an `id`, a `branch` built on top of the base branch, a `suffix` such as `-Optimistic+KSUN`, the `root` name shown in the release notes, and a `manager_nightly` download link. Rebase the variant branches every time the base branch moves; Prepare rejects any variant that has fallen behind.
3. If your source is not android14-6.1, read `scripts/build-optimistic.sh` first. It expects an ACK-style source tree with `build.config.constants`, `build.config.common` and `gki_defconfig`, and modules that are signed and uncompressed.
4. The flashing script lives in `anykernel/anykernel.sh`. The AnyKernel3 version is pinned by `AK3_COMMIT` in `release.yml`.
5. The release notes are generated by `scripts/release-notes.py`.

To build locally, run `scripts/build-optimistic.sh --help` for usage. The default paths match CI: `kernel/`, `toolchain/` and `out/` all sit in the repository root.
